07 · 后端技术栈 Backend

后端技术栈

前端组件区的另一半：Web 后端的一整套名词——从一次 HTTP 请求怎么走，到框架、数据库、API、认证安全、异步扩展、部署上线。能用毕设「智旅云图」举例的就拿它举，没有的就用通用例子。

FastAPI + Pydantic 数据校验/ 类型安全的入口
请求体 JSON
—
点「发送校验」看 FastAPI 怎么拦数据
FastAPI 在入口就用 Pydantic 把请求体校验一遍：字段类型、必填、范围不合格直接返回 422 错误列表。你代码里拿到的永远是正确的数据，不用自己写一堆 if 判空。
"后端用 FastAPI，请求体建一个 Pydantic 模型做校验，类型和范围错了返回 422"
RAG 检索增强生成/ 毕设的核心
RAG = 先检索知识库、再把命中的内容拼进 Prompt 喂给大模型，让答案有依据、少胡说。毕设里用 BM25 抓关键词、向量检索抓语义、重排把两路结果合并排序。
"实现 RAG：BM25 + 向量检索双路召回，重排后拼接上下文再调大模型生成"
RESTful API/ 前后端唯一的对话通道
GET/api/city/hangzhou/guide
POST/api/plan/generate
GET/api/poi/search?q=西湖&tag=长辈友好
—
路径 = 资源名，动词 = 动作。前后端 90% 的沟通就是「发请求、收 JSON」。
REST 的规矩：URL 只写名词（资源），动作交给 GET/POST/PUT/DELETE，结果用状态码表达（200 成功 / 404 找不到 / 500 服务器炸了）。
"帮我设计 RESTful API：行程生成走 POST /api/plan/generate，城市攻略走 GET /api/city/{city}/guide"
SQLite 数据库/ 表就是 Excel 页签
关系型数据库把数据存成一张张表，行 = 一条记录，列 = 字段。ORM（SQLAlchemy）让你用 Python 对象操作表，不用手写 SQL 字符串。
"用 SQLite + SQLAlchemy 建三张表：用户、行程、景点，外键关联 user_id"
同步 vs 异步/ FastAPI 为什么快
点按钮跑一遍
同步：三个请求排队等，总耗时 ≈ 2.1s；异步：三个请求同时发出、一起等，总耗时 ≈ 0.75s。请求卡在网络/数据库时不占 CPU，async 就是把「等」这件事并发掉。
"FastAPI 接口用 async def，同时调高德 API 和天气接口，别串行等"
JWT 登录态/ 无状态认证
登录成功后，这里会出现「盖章的通行证」——一段分成三截的 token。
登录成功发一个 JWT（三截：header.payload.signature），之后每次请求带上它，服务器验「章」不查数据库——所以叫无状态。前端存 localStorage 就行。
"登录接口返回 JWT，前端存起来，之后请求头带 Authorization: Bearer "
HTTP 请求解剖/ 一次请求长什么样
GET /api/city/hangzhou/guide HTTP/1.1

点上面按钮看请求的三部分；下面还能看状态码。
状态码 = 服务器给请求的「回执单」：2xx 成功、3xx 重定向、4xx 你的问题、5xx 我的问题。点分类看例子。
HTTP 是前后端通信的「快递单」：请求行写要什么（方法 + 路径），请求头写附加信息（认证、格式），请求体装数据；服务器回一个状态码 + 响应体。
