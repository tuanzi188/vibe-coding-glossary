01 · 需求与页面

M1

把“我想做一个行程管理”改写成页面目标、数据字段和验收标准。

  • 用户能看到行程列表和状态；
  • 用户能新增一条行程；
  • 空数据、错误和重复操作都有反馈。
产出：需求说明、页面草图、第一条 Git 提交。

02 · 前端交互

M2 → M4

用原生 JavaScript 管理表单、筛选、分页和状态，让页面先在浏览器里可用。

产出：`frontend/index.html`、`frontend/app.js`、成功 / 空数据 / 错误状态。

03 · 请求与接口

M5 → M6 → M9

把浏览器动作接到真实 FastAPI 接口，先约定请求体、响应体和状态码。

产出：`GET /api/trips`、`POST /api/trips`、`DELETE /api/trips/{id}`、`GET /healthz`。

04 · 数据与校验

M7

用 SQLite 保存行程，使用 Pydantic 校验输入，用分页和状态筛选控制数据范围。

产出：数据库表、初始化数据、非法输入的 422 响应、接口回归测试。

05 · 登录与权限

M8

下一阶段加入用户、Session 和数据归属。前端隐藏按钮不算权限，后端必须再次检查记录属于谁。

产出：注册、登录、退出、用户只能读写自己的行程。

06 · 测试与日志

M10 → M11

把主路径、边界条件和故障证据固定下来，让 AI 的修改可以回归验证。

产出：pytest、结构化日志、健康检查、故障复盘。

07 · 部署与复盘

M11 → M12

用 Docker 和环境变量启动，在新环境跑通后再总结这一轮 AI 协作方法。

产出：Docker Compose、README、部署差异、回滚步骤和 M12 复盘。
