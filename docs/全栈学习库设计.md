### 3.3 架构（v3 定案：两文件 + 三件套）

#### 决策：两文件

```
index.html      全栈学习库：13 模块全部课程 + 演示，模块切换式（目录总览 → 进入模块）  ~12,000 行
project.html    主线项目：行程管理全栈应用，8 步推进（目标→写→跑→验收）               ~1,000 行
```

- **为什么两文件**：「学」和「做」分离，概念零歧义——学习库是课程+演示（一个整体），主线项目是跟着做的动手页（节奏不同，独立最顺）；
- **为什么 index 敢到 12,000 行**：读者是初学者，用浏览器打开，不是用编辑器打开。浏览器渲染 1MB HTML 秒开、零压力（现状 5,460 行即证）。「编辑器卡」只发生在用户自己改代码时——而维护由脚本体系承担；
- **模块切换机制**：index 不搞 12,000 行平铺滚动，把现有路由（`initRoutes` / `LEARN_ROUTES`）扩展为「模块切换」——打开默认显示目录总览 + 当前模块，其他模块懒渲染/切换加载。体验像「一个 app 的多屏」，不是「一个 850KB 的卷轴」。

#### 单文件决策三件套（现在定，不往后放）

| 件 | 约定 |
| --- | --- |
| **1. 目录约定（现在定）** | ① section id 规范（已有）② **CSS 作用域类前缀强制**（模块级前缀如 `.lang-*`，已开先例）③ **模块间 JS 引用登记**：每模块结束时列一份「它引用了别的模块哪些 id」清单 |
| **2. 可拆性实测（每阶段验收项）** | 跑脚本查跨模块 `getElementById` 引用数 + CSS 跨模块依赖，记入文档。**触发线：预算超限 或 可拆性超标（跨模块引用 > 50 条）**——不再干等行数 |
| **3. 拆分预案（现在写好，触发才执行）** | 任一 section 平移出独立页（id 保留不变）；公共样式抽 `common.css` 或各页内联同一份保离线；跨页跳转 `?section=` + 落地恢复 |

#### 红线逻辑校准

| 红线 | 口径 |
| --- | --- |
| 可读性红线（主） | 浏览器打开秒开、交互流畅——1MB 内无压力，12,000 行不破 |
| 维护成本线（辅） | 靠脚本体系兜底：Grep 现取锚点 + 脚本替换 + 每轮 `node --check` + div 配平验证，大文件可控 |
| 预算控制 | 每批净增 ≤ 600 行（HTML+CSS+JS 合计）；超预算先做「卡级压缩」再进下一批 |

## 8. 第一批：语言层（详设）

挂在 M2 模块里（模块切换骨架已落地，侧栏一级目录里是「M2 JS/TS 语言基础」）。章内新增侧栏二级目录项由 `MODULES[].anchors` 登记。

| # | 区 / 锚点 | 三秒句 | demo 交互 | 验收（交互 ｜ 工程） |
| --- | --- | --- | --- | --- |
| 1 | 变量与作用域 `#langScope` | `var` 只认函数边界，`let`/`const` 认花括号；`const` 是「不许换人」，不是「内容不能改」 | 点 `var`/`let`/`const`，关键字高亮 + 两行结论变：块外能读吗 / 能重新赋值吗 | 三关键字两结论都对，`const` 重新赋值报 TypeError ｜ 能说出默认 `const` 的工程理由（不可变绑定砍掉意外赋值整类 bug） |
| 2 | 函数与 this `#langThis` | `this` 是**调用时站在谁身上**——看怎么调用，不看在哪定义（箭头函数反过来） | 四按钮实时显示 this 是谁（第 3、4 个正对应 setTimeout 丢 this 的真实 bug） | 四种调用四种结果，第 3、4 相反 ｜ 能指出第 3 种错在「依赖是隐式的」，不是 "`this` 坏了" |
| 3 | 数组三件套 `#langArray` | `map` 一条换一条，`filter` 挑合格的变少，`reduce` 压成一个值 | 4 条行程数据四栏并排：原始/map/filter/reduce，点按钮只亮一栏 | 四栏同源、map 等长 filter 变短 reduce 一个值、原数组不动 ｜ 能说出「返回新数组」是框架状态更新（引用变化检测）的前提 |
| 4 | 异步与事件循环 `#langAsync` | JS 同一时刻只干一件事；慢活先挂起，当前代码跑完再按序回来 | 点运行，三条跑道（同步/微任务/宏任务）依次点亮，输出 1→2→3→4 逐行出现带解释 | 顺序必须同步→微任务→宏任务，重跑干净重来 ｜ 能说出「在请求里做重活」为什么拖垮整个服务 |
| 5 | 类型与模块 `#langType` | 冒号是**编辑器提前拦错**的检查条；`import/export` 是文件之间借东西，借的方向就是依赖方向 | 类型：左右对照无类型/带 TS 的同一函数，点「传对/传错」看编译期红线。模块：依赖图 A→B→C，点「C 反向 import A」**成环亮红告警** | 传错编译期就红、成环必告警 ｜ 能说出「错误发现得越早越便宜」、依赖应单向成环是坏味道 |

区②四种调用的预期结果（第 3、4 即真实修过的 bug）：

| 按钮 | this 是谁 | 结果 |
| --- | --- | --- |
| `obj.say()` | obj | `'行程清单'` ✅ |
| `const f = obj.say; f()` | window | `undefined` |
| `setTimeout(obj.say, 0)` | window | `undefined` ← this 丢了 |
| `setTimeout(() => obj.say(), 0)` | obj | `'行程清单'` ✅ ← 修法 |

语言层落选与去向：闭包（函数区深挖一句）；解构/展开（变量区深挖）；`try/catch`（异步区深挖）；正则/原型链/`class`（不做——对 vibe coding 读者收益低，且 AI 代劳率高）；事件冒泡/DOM API（M1 HTML/CSS 模块）；HTML/CSS 基础（独立成 M1，本节不再重复）。

章主线一句话：**让依赖更显式、让错误更早暴露**。

### 模块切换骨架：实现说明（阶段 0.5）

**单一数据源**：`MODULES` 数组（13 模块 + `home`），每项四个字段——`blocks`（可见性：该模块拥有的块选择器）、`anchors`（侧栏二级目录归属）、`status`（`ready` / `wip`）、`plan`（待建模块的规划条目）。

**可见性机制**：`.mod-off{display:none !important}` 只做隐藏，不覆盖元素自身 `display`（组件块各有 flex/grid，用 `display:block` 覆盖会破坏布局）。切换时先全隐，再放出当前模块的块**及其祖先**——所以 `#feEco`（M4 的块，住在 `#behavior` 内）被放出时，`#behavior` 会随之放行，而同容器里其他模块的兄弟块仍是隐藏。

**注册块要写到最细一级**：整块归某模块的写 section（如 `#layout`）；一段里混多模块的必须写到 demo 粒度（`#behavior` 拆给 M1/M4、`#backend` 拆给 M6/M7/M8/M10），否则放行一个 demo 会连带放出同容器里不属于本模块的兄弟。

**跨模块跳转**：已有功能（目录点击 / `flashDemo` / `focusTechCard` / 锚点 demo）统一走 `modEnsureFor(锚点)` —— 目标不在当前模块就先切过去，元素才可测量；跳转后 hash 同步到目标锚点，刷新与分享能回到同一处。

**两处判断（文档未明确、实现时定的，可随时改）**：

1. **24 个组件 demo 归 M1**：文档 §3.1 提到「31 个组件 demo 在隐式教 HTML/CSS」，但 §4 的模块表没写它们的归属。实现时把 `#layout`/`#nav`/`#form`/`#feedback`/`#display` 归给 M1，M1 状态标 `ready`（已有内容可看），待补盒模型/语义化/响应式等显性 demo。
2. **`#techPanorama`（62 卡全景）整套挂 M6**：它按 `data-cat` 分 7 类，横跨 M6/M7/M8/M10。整块挂 M6 先保证可看，卡的分类归属留待各模块内容落地时按 `data-cat` 拆。
